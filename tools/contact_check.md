# Contact check — ตรวจจุดแตะของลูกบอลหัววัดจาก B-Rep

โปรแกรมแยกจากแอปหลัก (`tools/contact_check.py`) ใช้ตรวจว่า **จุดแตะที่แอปคำนวณจากไฟล์ STEP ถูกต้อง**
และแสดงว่า **สูตรประมาณผนังเป็นกรวยที่ระดับชั้น** (วิธีเดิม) คลาดเท่าไรบนผิวแต่ละแบบ
ผลทั้งหมดเป็นการตรวจเชิงคำนวณ ไม่ใช่ผลวัดจากเครื่อง

## วิธีใช้

```
python tools/contact_check.py                     # เปิดหน้าต่าง → เปิดไฟล์ STEP… → Run
python tools/contact_check.py ไฟล์.step --cli      # พิมพ์ตารางในคอนโซล
python tools/contact_check.py ไฟล์.step --cli --csv ผล.csv --r 1.0 --layers 3 --points 4
```

ต้องรันด้วย Python ชุดเดียวกับแอป (มี CadQuery/OCP, numpy, customtkinter)
ค่าตั้ง: รัศมีลูกบอล R (ค่าเริ่มต้นจาก `ProbeProfile` = 1 มม.), จำนวนชั้น, จุดต่อชั้น, มุมมอง

## ส่วนประกอบ

| ส่วน | มาจาก | หน้าที่ |
|---|---|---|
| โหลด STEP + สกัดรู + สร้างจุดวัด | โค้ดของแอป (`core/geometry_engine.py`, `core/gcode_generator.py::build_point_map`) | ได้จุดวัดชุดเดียวกับที่แอปส่งไปเครื่อง: จุดเริ่ม S, ทิศเดิน n, จุดคาดหวัง E, ตารางจุดแตะของแอป |
| ระยะถึงผิว | OpenCascade `BRepExtrema_DistShapeShape` | ระยะที่ใกล้ที่สุดจากจุดหนึ่งถึงผิว B-Rep |
| ชนิดผิว + พารามิเตอร์ | OpenCascade `BRepAdaptor_Surface` | บอกว่าเป็นระนาบ/ทรงกระบอก/ทรงกรวย/ทรงกลม พร้อมรัศมี แกน มุม |
| ส่วนตรวจ (เขียนใหม่ทั้งหมดในไฟล์นี้) | `tools/contact_check.py` | 4 การคำนวณด้านล่าง |
| หน้าต่าง | customtkinter (ชุดเดียวกับแอป) | ตาราง สรุป บันทึก CSV |

ไม่ได้เรียก `core/surface_oracle.py` (วิธีหาจุดแตะของแอป) — นั่นคือสิ่งที่ถูกตรวจ

## สิ่งที่คำนวณต่อจุด

1. **|E − CAD|** — ระยะจากจุดคาดหวัง E ถึงผิว CAD → ควรเป็น 0
2. **วิธีอ้างอิง** — ลูกบอลแตะผิวเมื่อ "ระยะจากศูนย์ลูกบอลถึงผิวที่ใกล้ที่สุด = R"
   เลื่อนศูนย์ลูกบอลไปตามเส้นทาง S + s·n ทีละ R/4 (ลูกบอลกว้าง 2R จึงข้ามผิวไปไม่ได้)
   จนระยะ ≤ R แล้วแบ่งครึ่งช่วง (bisection) 40 รอบ ได้ s_ref ละเอียดกว่า 10⁻¹² มม.
3. **สูตรตรง** — ศูนย์ลูกบอลที่แตะผิวต้องอยู่บนผิวที่ขยายออกไป R ฝั่งเดียวกับลูกบอล
   - ระนาบ → ระนาบที่เลื่อนไป R
   - ทรงกระบอกรัศมี Rc → ทรงกระบอกรัศมี Rc ∓ R
   - ทรงกลมรัศมี Rs → ทรงกลมรัศมี Rs ∓ R
   - ทรงกรวยมุม α → กรวยมุมเดิม รัศมีเลื่อนไป R / cos α

   แก้สมการเส้นตรงตัดผิวนั้น (สมการกำลังสอง) ได้ s_analytic — วิธีนี้ไม่ใช้การหาระยะของ OpenCascade เลย
4. **สูตรกรวย (วิธีเดิม)** — ถือว่าผนังเป็นระนาบสัมผัสที่ E: s_cone = s_E − R / (m·n)
   (m = ทิศตั้งฉากผิวที่ E ชี้เข้าเนื้อ, s_E = ระยะเดินถึง E)

ตารางแสดง แอป − อ้างอิง, สูตรตรง − อ้างอิง (ทั้งสองควร ≈ 0) และ กรวย − อ้างอิง (= ความคลาดของวิธีเดิม)
เกณฑ์ผ่าน 1 µm (`PASS_TOL`) แถวเหลือง = สูตรกรวยคลาดเกิน 0.01 มม. (`CONE_WARN`)

## ผลที่ได้ (6 พ.ย. 2569, R = 1 มม., 3 ชั้น × 4 จุด)

| ไฟล์ | จุด | แอป − อ้างอิง สูงสุด | สูตรกรวยคลาดสูงสุด |
|---|---|---|---|
| taper test .STEP (กรวย 15°) | 12 | < 0.001 µm | 0.0000 มม. |
| test 2 shpere.STEP (หลุม R10) | 12 | < 0.001 µm | 0.0039 / 0.0222 / 0.1276 มม. (ชั้น 1/2/3) |
| plate_with_holes, pocket_test, PTB01, ring_gauge_D20 | 12–84 | < 0.001 µm | 0.0000 มม. |

บนหลุม R10 ลูกบอลแตะต่ำกว่าระดับชั้น 0.28 / 0.56 / 0.83 มม. ทิศผิวคลาด 1.7° / 3.8° / 7.9°
ตรวจด้วยมือได้: ศูนย์ลูกบอลอยู่บนทรงกลมรัศมี R − r → x = √((R − r)² − h²)

ทดสอบว่าเครื่องมือจับความผิดได้: ใส่ค่าผิด 5 µm ในตารางของแอปชั้นที่ 3 → เครื่องมือแสดง 5.000 µm และไม่ผ่าน 4 จุดของชั้นนั้น

## ข้อจำกัด

- ตรวจเฉพาะจุดบนผนัง (ไม่รวมพื้นก้นรูและจุด Set up)
- สูตรตรงใช้ได้กับระนาบ ทรงกระบอก ทรงกรวย ทรงกลม — ผิวอื่น (ทอรัส, B-spline) แสดง "—" และตรวจด้วยวิธีอ้างอิงอย่างเดียว
- วิธีอ้างอิงกับแอปใช้คำสั่งหาระยะของ OpenCascade ตัวเดียวกัน (คนละวิธีค้นหา) ส่วนสูตรตรงไม่ใช้เลย จึงเป็นตัวตรวจที่แยกขาดที่สุด
- ถูกต้องเทียบกับชิ้นงานที่ตรงตาม CAD — ไม่ได้บอกความแม่นยำของการวัดจริง
